# 草场设计 GRASSLAND.md

草场网格的数据结构、消耗与恢复、以及它如何被牛和 shader 读取。
对应 DECISIONS D12、BEHAVIOR §4。本文是 §4 的实现级展开，§4 只留概念。

更新：2026-09-07 · 状态：设计定稿，待实现（M3-1）

---

## 0. 这个系统存在的理由

草场是全游戏唯一一个**以天为单位**的决策层。没有它，每一天都是同一天：牛在随机位置吃随机的草，玩家没有理由把群往任何特定方向带。

有了它，一条因果链成立：

```
今天在哪吃 → 明天那里草少 → 头牛自己往别处走 → 玩家发现群在漂移
→ 玩家开始有"这片吃了三天了，该往北坡带"的想法
```

这条链上**玩家不需要任何新操作**，只是他现有的操作（乌尔朵、吆喝、身位）有了跨天的意义。这是我们要的：策略层不增加操作量。

**反面**：草场不该变成资源管理。没有草量 UI、没有数字、没有"草场健康度"面板。玩家只能用眼睛看（P1 可视化）和用牛的行为推断（牛开始往外走 = 这里吃差不多了）。

## 1. 网格

| 参数 | 值 | 理由 |
| --- | --- | --- |
| 地图边长 | 400 m | 见 DECISIONS T20 |
| 格边长 | 10 m | BEHAVIOR §4 已定。一头牛吃草时的活动范围约 3–8 m，一格容得下一头牛的一次驻留 |
| 网格尺寸 | 40 × 40 = 1600 格 | 小到可以每帧全扫，也小到可以整个塞进存档 |
| 原点 | 地图中心 = 格 (20, 20) 的角 | 世界坐标 → 格：`floor((pos + 200) / 10)` |

1600 格意味着：全网格每日恢复是一次 1600 次的循环，一帧内跑完毫无压力；存档里 1600 × 2 个浮点，压缩后几 KB。**不需要任何优化**，朴素实现即可（与 T13 同一原则）。

### 1.1 每格字段

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `grass` 草量 | 0–1 | 当前可食草。0 = 吃秃，1 = 齐膝 |
| `degradation` 退化 | 0–1 | 过牧累积的损伤。只影响恢复速度，不直接影响可食量 |

两个字段刻意分开：**草量是短期的、可见的；退化是长期的、隐形的**。玩家看到草回来了就以为没事了，但连吃三天的地方恢复得越来越慢——这个"慢性代价"是草场系统的深度所在，也是它值得做的原因。

### 1.2 存储：一张 Image

用 `Image`（`FORMAT_RGF`，40×40，R = 草量，G = 退化）而不是 `PackedFloat32Array`。理由：

1. **可视化零成本**。`ImageTexture.create_from_image()` 直接喂给草的 shader，P1 的草量可视化不需要另建一套数据通路
2. 读写都是 `get_pixel/set_pixel`，够快（1600 格）
3. 存档时 `image.save_png_to_buffer()` → base64，或者干脆按行展开成两个浮点数组写进 JSON（T15 要求 JSON，见 §5）

代价是精度只有 float32 且要走 Color 语义，都无所谓。

## 2. 消耗

### 2.1 吃草

牛处于 GRAZE 状态时，每秒：

```
eaten = graze_rate × delta          # 从所在格扣除
grass[cell] -= eaten
satiety += eaten × satiety_per_grass
```

**`graze_rate` 的定标是整个系统的调速旋钮。** 从"一片好草场能撑多久"倒推：

- 一天 1800 s（DECISIONS D4），牛约有 55% 的时间在 GRAZE（其余漫步/休息/跟随），即 ~1000 s/天
- 5 头牛 = 5000 牛·秒/天
- 希望：**5 头牛在一片 5×5 格（50×50 m，牛群自然散布的范围）上吃一天，草量从 1.0 降到约 0.55**
- 25 格 × 0.45 = 11.25 总草量/天，除以 5000 牛·秒

```
graze_rate = 0.00225 /秒   →  取整为 0.0025
```

含义：一头牛连续吃草 400 秒可以把一整格从 1.0 吃到 0。听起来快，但牛不会站在一格里吃 400 秒——它会漫步、会跟着头牛走，实际是分散在十几格上的。

**验算**：单头牛一天吃掉 1000 × 0.0025 = 2.5 格的草。5 头 = 12.5 格。与上面倒推的 11.25 吻合（差值来自取整）。

| 参数 | 值 | 状态 |
| --- | --- | --- |
| `graze_rate` | 0.0025 草量/秒 | 暂定，M3 手感测试中调 |
| `satiety_per_grass` | 0.12 饱腹/草量 | 暂定。含义：吃掉一整格的草 = 一头牛 12% 的饱腹度 |

### 2.2 草量影响吃草效率

BEHAVIOR §4：草量低于 0.3 时效率明显下降。具体曲线：

```
efficiency(g) = clamp(g / 0.3, 0.15, 1.0)
```

- g ≥ 0.3：满效率
- g = 0.15：半效率
- g → 0：留 0.15 的地板，不归零

**为什么留地板**：效率归零会让牛在吃秃的地里"卡住"（吃不饱 → 一直想吃 → 但吃不到）。留 15% 保证它总能缓慢积累饱腹度，最终自然进入漫步。**行为系统里任何会导致死锁的零值都要留地板**，这条是通则。

实际饱腹增速 = `graze_rate × efficiency(g) × satiety_per_grass × greed`（greed = 性格参数，BEHAVIOR §2）。

### 2.3 草量驱动行为（不写脚本的"自己走开"）

草场不主动指挥牛，只改三个已有的权重。这是设计上的关键：**草场是一个场，不是一个 AI**。

| 接入点 | 规则 |
| --- | --- |
| GRAZE 时长 | `duration × (0.4 + 0.6 × efficiency)`。草好就多待，草差就短促结束 |
| GRAZE → 下一态权重 | `efficiency < 0.5` 时 WANDER 权重 ×2.5，REST 权重 ×0.3 |
| WANDER 选点 | 现有的 6 个候选点评分里加一项 `× (0.3 + grass_at_candidate)` |
| 头牛挑草场 | 见 §3 |

这四条加起来，"牛群会自己离开吃秃的地方"就是涌现的，没有一行代码写"如果草秃了就走开"。

## 3. 头牛挑草场

BEHAVIOR §3 说"每 5–10 分钟评估半径 40 m 内草场格，选草量最高的一块"。一天 1800 s 下这个周期需要重定：

**周期改为 每 150–300 s（2.5–5 分钟）**，一天里发生 6–12 次。理由：8 分钟一天时 5–10 分钟意味着一天只挑 1 次，群几乎不漂移；30 分钟一天下，一天 6–12 次漂移才能让玩家看出"群在慢慢移动"。

**评估算法**：

```
候选 = 半径 [15, 45] m 环形内随机采样 12 格
评分 = grass × 距离衰减 × 方向惯性 × 归栏偏置
选最高分的格中心作为 PURPOSEFUL_MOVE 的目标
```

四个因子的作用：

| 因子 | 公式 | 为什么 |
| --- | --- | --- |
| `grass` | 格草量 0–1 | 主项：往草多的地方去 |
| 距离衰减 | `1 - 0.5 × (d / 45)` | 近处优先，避免头牛每次都冲向地图边缘的最优格 |
| 方向惯性 | `0.7 + 0.3 × dot(方向, 上次方向)` | 群的漂移是连贯的一条弧线，不是布朗运动。**这一条是"可信"的关键** |
| 归栏偏置 | `lerp(1.0, 指向围栏的 dot 归一化, homing_urge)` | 傍晚起，候选格越靠围栏方向分越高。见 DAY_CYCLE §3 |

内环 15 m 是为了不选"脚下这一格"——否则头牛会原地打转。

**这是全游戏最重要的一段涌现行为**：玩家看到的"牛群在山坡上缓慢地、有方向地移动"完全来自这 12 个采样点和 4 个乘数。M3 调参时它应该排在最前面。

## 4. 恢复

`Clock.day_ended` 触发（T17：只有 Clock 能计时），对全部 1600 格执行：

### 4.1 草量：逻辑斯蒂增长

```gdscript
grass += r * grass * (1.0 - grass) * (1.0 - degradation)
```

r = 0.35/天（BEHAVIOR §4 已定）。

逻辑斯蒂的性质正是我们要的：**吃秃的地方恢复得最慢**。g=0.5 时增量 0.0875（最快）；g=0.05 时只有 0.0166。

**但它有个致命性质：g = 0 时增量恒为 0，永不恢复。** 必须加一个种子项：

```gdscript
grass = min(1.0, grass + r * grass * (1 - grass) * (1 - degradation) + seed_growth * (1 - degradation))
seed_growth = 0.02   # 每日无条件回一点，代表风带来的种子
```

（同 §2.2 的地板原则：任何会导致永久死锁的零值都要留出口。真正吃秃的地要 15+ 天才回得来，这已经足够是惩罚了，不需要"永远回不来"。）

### 4.2 退化

```gdscript
if grass < 0.1:
    degradation = min(1.0, degradation + 0.15)   # 吃秃一天，+0.15
else:
    degradation = max(0.0, degradation - 0.02)   # 否则每日自愈 0.02
```

自愈 0.02/天（BEHAVIOR §4 已定），累积 0.15/天是新定的。这个比例（累积是自愈的 7.5 倍）意味着：**吃秃一天，要 7 天不碰才能抹掉。** 连吃三天（degradation → 0.45），恢复速率打对折，要三周。

这就是 PRD §5.4 验收标准想要的："同一块草场连放三天，牛群明显向外扩散；第四天起放别处，一周后原地恢复。"

### 4.3 验收用的数值推演

一格从 1.0 开始，被连续吃秃三天后放置不管：

| 天 | 草量 | 退化 | 说明 |
| --- | --- | --- | --- |
| 0 | 1.00 | 0.00 | 初始 |
| 1–3 | ~0.05 | 0.45 | 连吃三天，退化累积 |
| 4 | 0.07 | 0.43 | 恢复极慢 |
| 7 | 0.14 | 0.37 | 肉眼能看出一点绿 |
| 12 | 0.42 | 0.27 | 明显回来了 |
| 18 | 0.85 | 0.15 | 基本恢复 |

**一块被吃秃的地要将近三周才真正回来。** 地图 1600 格、群只有 5–20 头，这个惩罚不会让玩家无草可吃，只会让他慢慢学会轮牧。强度合适。

## 5. 初始分布

**不要均匀 1.0。** 均匀草场的后果是头牛的挑草场评分退化成纯距离项，群不会漂移，整个系统白做。

用两层噪声：

```gdscript
base = FastNoiseLite(frequency = 0.012, seed = map_seed)   # 波长 ~85 m，"好坡 / 差坡"
detail = FastNoiseLite(frequency = 0.05, seed = map_seed + 1)  # 波长 ~20 m，格间差异
grass = clamp(0.55 + 0.35 * base + 0.12 * detail, 0.05, 1.0)
degradation = 0.0
```

结果：地图上有几片明显更肥的区域（草量 0.85+）和几片贫瘠区（0.2 以下），中间过渡。**头牛第一天就会往肥的地方走，玩家第一天就能看到群在漂移。**

围栏周围 3 格半径内草量 ×0.6：牲口每天出入踩踏，围栏边是秃的——这既是真实的，也在功能上鼓励玩家把群带远，否则围栏边很快就吃没了。

## 6. 可视化（P1，M3 数据跑通后）

草量 → 草的高度与颜色，走已有的 `grass.gdshader` + MultiMesh（`scripts/world/grass_field.gd`）。

**通路**：`GrassField` 持有的 `ImageTexture` 作为 uniform 传给 shader；顶点着色器按实例的世界 XZ 采样：

```glsl
uniform sampler2D grassland_tex;   // R = 草量, G = 退化
vec2 uv = (world_xz + 200.0) / 400.0;
float g = texture(grassland_tex, uv).r;
VERTEX.y *= mix(0.25, 1.0, g);            // 秃地的草矮
COLOR.rgb = mix(DRY_YELLOW, LUSH_GREEN, g);
```

三条视觉规则：

1. **高度比颜色更重要**。矮草比黄草更能读出"这里被吃过"，因为高度差在远景俯视下依然可见
2. **秃地是土黄不是焦黑**。高原的秃地是干草色，不是死地。避免让玩家觉得自己在破坏环境（PRD：不说教）
3. **退化不做视觉表达**。它是隐形的长期代价，玩家应当通过"这里怎么老长不回来"来体会，而不是看一层红色 overlay

每日恢复后更新一次纹理即可，不需要每帧。

## 7. 接口

`GrassField` 是唯一的草场入口，autoload 不需要（它属于 world 场景），但要在组里便于查找：

```gdscript
class_name Grassland extends Node3D    # group: "grassland"

func sample(world_pos: Vector3) -> float          # 草量 0–1
func efficiency(world_pos: Vector3) -> float      # §2.2 的曲线
func consume(world_pos: Vector3, amount: float) -> float   # 返回实际吃到的量
func best_cell_near(origin, min_r, max_r, samples, bias_dir, bias_weight) -> Vector3   # §3
func daily_regrow() -> void                       # 接 Clock.day_ended
func to_save() -> Dictionary / func from_save(d)  # §5
```

**牛不持有格坐标**，每次按世界坐标查。1600 格的 `get_pixel` 足够便宜，持有格坐标只会带来"牛移动了但格没更新"这类同步 bug。

### 7.1 存档

JSON（T15），两个数组按行展开：

```json
"grassland": {
  "size": 40,
  "grass": [0.82, 0.79, ...],        // 1600 个，float 保留 3 位
  "degradation": [0.0, 0.0, ...]
}
```

保留 3 位小数即可，草量的精度对玩法无意义。1600 × 2 × ~5 字符 ≈ 16 KB，可接受。

## 8. 待调参数

M3 灰盒中调，调完把终值写回本文：

- `graze_rate` 0.0025（最重要，直接决定多日节奏）
- `satiety_per_grass` 0.12
- 效率曲线的拐点 0.3 与地板 0.15
- 头牛挑草场周期 150–300 s、采样数 12、四个因子的权重
- 恢复 r 0.35、种子项 0.02、退化累积 0.15 / 自愈 0.02
- 初始噪声的两个频率与幅度

调参目标：**玩家在第三天自己说出"这片草不太行了"**，而不是被任何 UI 告知。
