## 0. 一天 30 分钟意味着什么

D4 定为 **1800 秒**（DECISIONS 已更新）。这不是把 8 分钟的一天拉长 3.75 倍，而是换了一种东西。

8 分钟的一天是**一个关卡**：出栏、赶群、归栏，中间没有空隙，玩家全程在操作。
30 分钟的一天是**一段时光**：大部分时候什么都不发生，玩家坐着看，偶尔起身。

这正是 PRD §3 的体验承诺（"玩家愿意坐着看牛五分钟而不觉得无聊"）和 BEHAVIOR §0 的调性原则想要的。8 分钟其实太紧，装不下"中段几乎无事"。**30 分钟是把设计意图和时长对齐。**

但它带来三个必须正面解决的问题，本文第 1、2、4 节分别回答：

| 问题 | 回答 |
| --- | --- |
| 30 分钟里玩家实际在干什么？会不会真的无聊？ | §1.2 事件密度 |
| 玩家中途想走怎么办？30 分钟是很长的承诺 | §1.3 可中断性 |
| 400 m 的地图配 30 分钟，会不会太小太空？ | §2.1 |

### 0.1 不要用加速来解决无聊

一个诱人但错误的方案是加个"快进"键。**明确不做。**

一旦有快进，玩家会一直按着它，游戏就变回 8 分钟的版本，而且是带愧疚感的版本（"我在跳过内容"）。慢是这个游戏的内容本身，给一个跳过慢的按钮等于承认它是缺陷。

调试用的 `T` 键快进保留（`--debug` 下），发行版本移除。

## 1. 时间结构

### 1.1 时段划分

一天 1800 s，`time_of_day` 0.0 → 1.0。时段边界重新分配（现有 `clock.gd` 的值是按 8 分钟定的）：

| 时段 | `time_of_day` | 实时 | 长度 | 这一段是什么 |
| --- | --- | --- | --- | --- |
| 清晨 DAWN | 0.00 – 0.08 | 0:00 – 2:24 | 2.4 min | 出栏。群散开，玩家选个方向 |
| 上午 MORNING | 0.08 – 0.33 | 2:24 – 9:54 | 7.5 min | 主要放牧段。群漂移 2–3 次 |
| 正午 NOON | 0.33 – 0.47 | 9:54 – 14:06 | 4.2 min | 最静的一段。半数牛卧下反刍 |
| 下午 AFTERNOON | 0.47 – 0.72 | 14:06 – 21:36 | 7.5 min | 第二个放牧段。归栏欲望开始爬升 |
| 傍晚 EVENING | 0.72 – 1.00 | 21:36 – 30:00 | 8.4 min | 头牛带队回家，玩家收拢掉队的 |
| 夜 NIGHT | = 1.00 | — | — | 结算 |

三个刻意的选择：

**傍晚给到 8.4 分钟（全天 28%）。** 它是唯一一段玩家有明确目标的时间，也是唯一一段真的会失败的时间。它必须长到足够找回两三头掉队的牛——从地图任一点走回围栏最远约 280 m，跑步 5 m/s 要 56 s，来回两趟加上找牛，8 分钟刚好不慌张。**傍晚太短会让整个游戏变得紧张，这与调性直接冲突。**

**正午 4.2 分钟是故意的空白。** 群卧下不动，玩家无事可做。这是唯一一段"什么都不发生"的设计良品，不要试图填满它。它的功能是让"傍晚有事做"有对比，也让玩家有一段可以真的放下手柄的时间。

**清晨只有 2.4 分钟。** 出栏没什么内容，不要拖。

### 1.2 事件密度：30 分钟里到底发生什么

无聊的判定标准不是"是否一直有操作"，而是**是否一直有可看的变化**。列一天里的变化事件：

| 事件 | 频次/天 | 玩家感知 |
| --- | --- | --- |
| 头牛挑新草场，群漂移 | 6–12 次（GRASSLAND §3） | 主要的"画面在变" |
| 光色推进 | 连续 | 最重要的时间感来源 |
| 某头牛走远（合群低的个体） | 3–6 次 | 玩家可能起身，也可能不 |
| 牛卧下 / 起身 | 全天散布 | 群的姿态在变 |
| 牛铃、远处牛叫 | 稀疏 | 听觉上的"还活着" |
| 傍晚寺院号声 | 1 次（EVENING 起点） | 时间提示，也是情绪转折 |

**玩家的实际操作次数目标：一天 5–15 次乌尔朵，外加傍晚的一段步行。** 这就是"操作稀疏"的量化定义。

如果 M3 测试中发现无聊，**第一顺位的修法是提高漂移频率（让画面更常变），不是加事件、不是缩短一天。** 加事件会破坏调性；缩短一天是投降。

### 1.3 可中断性：30 分钟的承诺问题

30 分钟对休闲玩家是一个不小的承诺。必须让玩家能在任何时候放下：

1. **随时可退出，进度不丢。** 退出即写一份"当天中途"的存档（含 `time_of_day`），下次进来接着那一刻。这比"只在结算时存档"重要得多——只在结算存档等于强迫玩家一次玩满 30 分钟
2. **暂停不是菜单。** ESC 暂停时钟并淡出画面，不弹一堆选项。继续 / 保存并退出，两项
3. **不惩罚挂机。** 玩家去泡茶十分钟，回来牛群还在吃草，最多漂移了两次。这是设计保证，不是巧合——它要求"玩家不干预也不出事"（BEHAVIOR §0.1）在 30 分钟尺度上依然成立

**第 3 条是一条硬约束，它约束的是别的系统**：任何"玩家不管就会出事"的机制（比如白天的狼、比如牛会走出地图）都违反它，因此都不做。危险只存在于夜里（§5）。

## 2. 地图与围栏

### 2.1 地图边长 400 m

30 分钟的一天配 400 m，横穿只占全天 4%（走路 200 s）。这看起来太小——但**不应该按"填满时间"来定地图大小**。

按"群一天能吃多少"来定才对：5 头牛一天消耗约 12.5 格（GRASSLAND §2.1），恢复期约 15 天，稳态下需要约 190 格的轮牧面积。地图 1600 格，余量给到 20 头牛的后期规模（50 格/天 × 15 天 = 750 格）仍然够。**400 m 是按牧场承载力定的，不是按行走时间。**

至于"空"：玩家一天的实际活动范围是群周围 50–100 m，他不会横穿地图。地图的其余部分是**背景与去处**，不是待填充的内容区。

| 参数 | 值 | 状态 |
| --- | --- | --- |
| 地图边长 | 400 m（±200） | 已定（T20） |
| 围栏位置 | 西南象限，距地图中心约 90 m | 暂定 |
| 围栏尺寸 | 20 × 20 m（现状） | 暂定。20 头牛时若显挤再放大 |

围栏放偏一侧而不是正中：让"出栏"有一个明确的方向感（往地图中心去），也让归栏是一条有终点的路，而不是"回到中间"。

### 2.2 围栏

`scripts/world/pen.gd` 已实现：四边木栅栏带碰撞，东侧一道自动门（门前 7 m 内有牛或人则开，走空 2 s 后关）。本节只补它还缺的部分。

**自动门是对的，保留。** 它替代了"开关门的按键"——玩家不需要任何门相关的操作，但门的开合是一个可看的、有生活感的细节。这比一个静止的缺口好，也符合"操作稀疏"。

还需要补：

- **归栏判定的载体。** 现在判定散在 `Cow.is_in_pen` 里，靠 center + size 比较。改为 `Pen` 提供 `contains(pos) -> bool` 与 `cows_inside() -> Array[Cow]`，判定只有一处
- **`cow.gd` 硬编码的 `pen_center` 移除**，运行时从 `get_tree().get_first_node_in_group("pen")` 取。围栏挪位置时不需要改牛
- **牛不会自己乱出去。** 清晨的出栏是主动的（§3.1），其余时间牛没有理由回到围栏。门开着也一样——牛的目标点由挑草场决定，不由门决定

## 3. 出栏与归栏

### 3.1 出栏（DAWN）

天亮时群在围栏内。**自动散开，玩家不需要做任何事**（BEHAVIOR §0.1）。

**已实现。** 起始群生成在围栏内（`HerdManager.spawn_in_pen`）；DAWN 期间还在栏里的头牛，
挑草场的方向偏置取"背离围栏"且权重拉满，其余牛按正常的跟随力跟出去。DAWN 结束后恢复正常评估。
自动门（§2.2）本来就会为走近的牛打开，所以不需要任何额外的开门逻辑。

不做"开门""赶出去"的玩法。清晨的功能是给玩家看一眼今天的天色和群的状态，然后跟着走。

### 3.2 归栏欲望曲线

`Clock.homing_urge()` 现有实现是从正午起 `t²`。配合新的时段划分重定：

```gdscript
func homing_urge() -> float:
    if time_of_day < 0.47:      # 正午结束前，没有归栏念头
        return 0.0
    var t := inverse_lerp(0.47, 0.95, time_of_day)
    return clamp(t * t, 0.0, 1.0)
```

- 0.47（下午起点）开始离开 0，但 t² 让它前期几乎不可察觉
- 0.72（傍晚起点）时 urge ≈ 0.27，头牛的挑草场开始明显偏向围栏方向
- 0.95 时到 1.0，最后 5% 的时间（90 s）满值，头牛直奔围栏
- **不用线性**：线性会让整个下午都在往回走，玩家感觉一天下午都在收工

这条曲线接入 GRASSLAND §3 的"归栏偏置"因子。**头牛不是被脚本命令回家的，是它挑草场的口味逐渐偏向了家的方向。** 这个区别在玩家看来就是"牛自己慢慢往回走"而不是"到点了牛开始执行归栏"。

### 3.3 掉队

不是所有牛都会跟上。三类会掉队：

| 类型 | 原因 | 玩家怎么处理 |
| --- | --- | --- |
| 合群低的个体 | `sociability` < 0.85，跟随力不足 | 乌尔朵落一颗，或走近用吆喝 |
| 惊吓中的牛 | 傍晚被惊跑，跑反了方向 | 等它冷静（ALERT 结束）再推 |
| 吃到好草的牛 | 所在格草量高，GRAZE 时长被拉长 | 走近吆喝 |

**掉队是设计出来的，不是缺陷。** 如果所有牛都自动跟回去，傍晚就没有玩法了。目标是每天 **1–3 头**需要玩家介入：太少则傍晚无事，太多则变成赶羊任务。调 `sociability` 的分布下限来控制这个数。

### 3.4 天黑判定与宽限

`time_of_day` 到 1.0 时**不立即结算**。给 **60 秒宽限**（`GRACE_SEC = 60`），期间：

- 时钟停在 1.0，光线继续变暗（宽限期是可见的：天在黑下去）
- 玩家还能把最后一头牛推进围栏
- 全部牛入栏则立即结束宽限，不用等满

**为什么要宽限**：没有宽限，"差三秒"的失败会让玩家下次提前十分钟开始收工，整个傍晚变成焦虑的抢时间。宽限把硬截止变成软截止——玩家知道自己在赶，但知道赶得上。这直接服务 BEHAVIOR §0.6"失去是真实的，但不制造紧张"。

宽限结束 → `Clock.day_ended` → 结算。

## 4. 结算

PRD §5.13：一屏，三秒看完，无"完成"字样。

### 4.1 内容

```
                    第 4 天

              存栏   7 / 8
              奶     3
              毛     1

              ⚠ 灰额头没有回来

                 [ 睡觉 ]
```

规则：

- **不列清单，不算分，不显示"+N"的飘字**
- 数字用中文排版的疏朗间距，不用表格线
- 没回来的牛**用名字点出来**（"灰额头没有回来"），不用"1 头牲畜走失"。名字是玩家产生情感的唯一抓手（PRD §12：玩家能说出一头牛的特点）
- 全员归栏时不写"全部归栏"之类的褒奖，那一行直接不存在。**没有消息就是好消息**
- 唯一的按钮是"睡觉"，不是"确认"或"继续"

### 4.2 时机与呈现

天黑宽限结束 → 画面缓慢淡到深蓝（2 s）→ 文字淡入 → 停留直到玩家按键。**不要动画数字、不要音效奖励。**

结算是这个游戏的第一个 UI，它定下全部 UI 的调性：**安静、居中、字少、不庆祝。** 后面的商店（M5）照这个调子做。

### 4.3 产出

P0 只记数量入库，不能卖（PRD §5.6）：

| 产出 | 规则 | 状态 |
| --- | --- | --- |
| 奶 | 每头存栏成年牛，饱腹度 > 0.5 者产 0.5 单位，向下取整到整群 | 暂定 |
| 毛 | 每 3 天一次，每头存栏牛 0.5 单位 | 暂定 |

**饱腹度挂钩产奶**是把草场系统接到经济上的那一根线：草不好 → 牛吃不饱 → 产奶少。它让 GRASSLAND 不只是行为系统，还有玩法后果。数值 M5 定价时再调。

## 5. 走失与死亡

### 5.1 走失（P0）

天黑宽限结束时不在围栏内的牛 → 标记 `lost = true`，留在世界里过夜。

次日清晨重新投放：

```
候选 = 以它昨晚最后位置为中心、半径 [20, 60] m 内的格
评分 = 草量（走失的牛整夜在找草，会移动到附近草好的地方）
位置 = 最高分格的中心 + 随机偏移
```

它次日的状态是正常的 GRAZE，`lost` 标记清除，但**不属于任何群**（`_leader = null`），不会自己回家。玩家必须走过去，用身位或乌尔朵把它推回群的范围内（进入头牛的 `follow_start_distance`），它才重新入群。

PRD §5.7 验收："走失的牛能在次日 3 分钟内被找到"。半径 60 m 的投放保证了这一点——玩家知道它昨晚在哪，往那个方向走两分钟就能看见。

### 5.2 死亡（D5 待定 → 现定）

**决定：M6 之前只做一条来源——夜间未归栏遭狼。**

判定：一头牛连续 **两晚**未归栏，第二晚结算时有 **25%** 概率死亡。

四条设计约束解释这个规则：

1. **第一晚绝不死。** 第一晚走失是"出事了"，第二晚才是"我没去找它"。死亡必须是玩家的不作为造成的，而不是运气。**给玩家一整天的挽回窗口**是这条机制能被接受的前提
2. **25% 而不是 100%。** 即使第二晚也没找回，四次里有三次它还活着。死亡应当罕见到玩家记得住每一次
3. **夜里，看不见。** 玩家不会目睹狼。他只在结算时读到一行字。看不见的死亡比演出来的死亡更沉，也回避了做狼的 AI 和动画
4. **有现场。** 死亡地点留下一处痕迹（灰盒阶段是一堆白色小方块），永久留在地图上，不消失。PRD §5.7 验收要求"玩家知道发生了什么"

结算里的呈现：

```
              灰额头 死了
```

一行，没有别的。不解释原因，不给数字，不问"是否继续"。

**明确不做**（DECISIONS 第四节新增）：悬崖坠落、饥饿致死、白天的任何危险。前两者需要地形与长期饱腹度都很扎实，后者违反 §1.3 第 3 条（不惩罚挂机）。

## 6. 一天的状态机

```
        ┌──────────────────────────────────────┐
        ↓                                      │
   [DAWN 出栏] → [白天 放牧] → [EVENING 归栏]  │
                                    ↓          │
                            [宽限 60 s]        │
                                    ↓          │
                            [结算 · 走失/死亡判定]
                                    ↓          │
                            [睡觉] ────────────┘
                              ↓
                          [自动存档]
```

单一驱动源是 `Clock`（T17）。围栏、草场、结算、走失全部挂 `Clock` 的信号，任何节点不得自行计时。

`Clock` 需要新增：

```gdscript
signal grace_started()          # time_of_day 到 1.0
signal day_ended(day: int)      # 宽限结束（已有）
var in_grace: bool
```
