## 二、设计决定

| # | 事项 | 决定 | 状态 |
| --- | --- | --- | --- |
| D1 | 时代设定 | 当代藏区 | 已定 |
| D2 | 地图结构 | 长期：分段驻扎，一处待数日后转场。**当前只做一张地图**，转场与多地图在核心循环验证后再议 | 已定 |
| D3 | 牲口种类 | 当前只有牛（牦牛）。羊等其他种类后续再加，群体行为参数按种类独立配置 | 已定 |
| D4 | 一天长度 | 实时 6–10 分钟，具体数值在 M3 手感测试中定 | 暂定 |
| D5 | 牲口的丢失与死亡 | **会丢，会死，尽量真实。** 天黑未归栏的牲口次日出现在地图某处需寻回。死亡来源（狼、悬崖、掉队等）待定，M3 前先实现丢失 | 已定 |
| D6 | 产出与货币 | 单一货币（现金）。牲口按存栏产出奶与毛，奶、毛与牲口本身均可出售换取现金 | 已定 |
| D7 | 惊吓机制 | 群体有惊吓值。玩家移动越快施压越强、效率越高，但越易冲散群体。载具因此是取舍而非纯数值升级：步行稳而慢，骑马居中，摩托快而易惊群 | 已定 |
| D8 | 养成范围 | 现金用于扩群、购置载具、升级住宅。无作物、无季节、无好感度系统 | 已定 |
| D9 | 地标功能 | 玛尼石堆、佛塔、寺院承担导航、存档、地图解锁、委托发布等功能。宗教场所不做交易；买卖放在牧民帐篷与村镇 | 已定 |
| D10 | 休闲的定义 | 休闲指操作量少、节奏舒缓，不指后果轻。允许真实的失去 | 已定 |
| D11 | 操作模型 | 玩家不直接控制牛，只通过施压影响。两种施压：身位（近距离、连续）与乌尔朵（远距离、离散）。玩家大部分时间远观，偶尔干预。详见 `docs/BEHAVIOR.md` §6 | 已定 |
| D12 | 草场系统 | 地形覆盖网格数据层，每格有草量与退化值。牛按草量决定吃与走，草场按日恢复，过牧退化。详见 `docs/BEHAVIOR.md` §4 | 已定 |
| D13 | 头牛 | 群体聚合力指向头牛而非质心。头牛负责挑草场与傍晚认路归栏。头牛丢失后群分裂，隔夜自动产生新头牛。详见 `docs/BEHAVIOR.md` §3 | 已定 |

## 三、待定

M3 前必须决定：

- 死亡的具体来源与判定（D5）
- 一天的实时长度（D4）
- 地图尺寸（依赖 D4：按步行一分钟穿越估算，边长约 300–400 米）
- 起始牲口数量与起始现金

核心循环验证后再议：

- 转场是否可玩（Herdling 式线性行程）还是过场
- 多地图与驻扎天数
- 羊及其他牲口种类
- iOS 移植（若做，渲染器切换至 Mobile，操作方式需重做）

## 四、明确不做

- 作物 / 种植系统
- 季节系统
- NPC 好感度
- C# 或其他语言
- 自由旋转俯仰的相机
- 在 M3 之前进行任何美术或 UI 打磨
